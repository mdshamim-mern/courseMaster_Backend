CourseMaster Assignment 4 Bug Report

Prepared for mdshamim-mern on 31 October 2026

This report records 31 reproducible or source-substantiated CourseMaster defects, their fixes, and their verification evidence. All eight previously pending browser scenarios now have passing results. The checks used isolated local MongoDB data and an isolated Chrome profile; the original upstream repositories were not modified.

Verification results

Verification passed: 19 backend HTTP scenarios, 7 frontend regression checks, 21 problem-solving tests covering all 20 assigned problems, and all 8 browser scenarios. Seven browser scenarios passed in the full run; the session-recovery scenario passed in a targeted rerun after its transient-error logout defect was fixed. ESLint and the production build pass. The build has a nonfatal DaisyUI CSS optimization warning for @property.

The mobile and desktop checks used widths of 390 and 1366 pixels. External YouTube iframe requests were blocked during layout verification, so these results do not claim third-party video playback verification. No production deployment was performed. No private credentials or .env files were committed.

Detailed bug reports

BUG-001 Valid passwords cannot log in

  1. Bug ID and title: BUG-001 — Valid passwords cannot log in
  2. Location and steps: backend/src/services/auth.service.js. Register a student, then submit the same email and password to POST /api/auth/login.
  3. Expected versus actual: A valid password should authenticate. The original returns 400 Invalid email or password because plaintext is compared to the hash.
  4. Severity and evidence: High; priority P1. HTTP regression: correct password succeeds and incorrect password fails.
  5. Fix and verification status: Use await bcrypt.compare. Status: Fixed & Verified.

BUG-002 First enrollment is rejected

  1. Bug ID and title: BUG-002 — First enrollment is rejected
  2. Location and steps: backend/src/services/enrollment.service.js. Use a valid student token and POST /api/enrollments/:courseId for a course the student has not joined.
  3. Expected versus actual: First enrollment should return 201. The original returns Already enrolled in this course when no enrollment exists.
  4. Severity and evidence: High; priority P1. HTTP regression: first enrollment 201; duplicate enrollment 400.
  5. Fix and verification status: Reject an existing enrollment, then create the new enrollment. Status: Fixed & Verified.

BUG-003 Invalid tokens reach protected controllers

  1. Bug ID and title: BUG-003 — Invalid tokens reach protected controllers
  2. Location and steps: backend/src/middlewares/authMiddleware.js. Send an invalid Bearer token to GET /api/auth/me.
  3. Expected versus actual: Invalid authentication should return 401. The original calls next and returns a controller error with status 404.
  4. Severity and evidence: High; priority P1. HTTP regression: invalid token returns 401.
  5. Fix and verification status: Return 401 immediately when JWT verification fails. Status: Fixed & Verified.

BUG-004 Admin registration key is ignored

  1. Bug ID and title: BUG-004 — Admin registration key is ignored
  2. Location and steps: backend/src/services/auth.service.js. Register with an invalid adminKey, then register another user with the configured valid admin key.
  3. Expected versus actual: An invalid key should fail; a valid key should create an admin. The original silently creates a student even for an invalid key.
  4. Severity and evidence: High; priority P2. HTTP regression covers valid and invalid keys and injected role rejection. The original route schema already stripped role; no HTTP role-escalation claim is made.
  5. Fix and verification status: Validate adminKey on the server and derive the role from that validation. Status: Fixed & Verified.

BUG-005 Quiz percentage is ten times too small

  1. Bug ID and title: BUG-005 — Quiz percentage is ten times too small
  2. Location and steps: backend/src/services/quiz.service.js. Submit correct answers to every question through POST /api/quizzes/submit.
  3. Expected versus actual: A perfect score should return 100 percent. The original returns 10 percent.
  4. Severity and evidence: High; priority P1. HTTP regression checks perfect score, zero score, retakes, and latest-attempt statistics.
  5. Fix and verification status: Multiply the score ratio by 100. Status: Fixed & Verified.

BUG-006 Malformed quiz answers are accepted

  1. Bug ID and title: BUG-006 — Malformed quiz answers are accepted
  2. Location and steps: backend/src/services/quiz.service.js. Submit an answer array containing option index 999, a negative index, a string, or the wrong number of answers.
  3. Expected versus actual: Invalid answer structures should return 400. The original accepts out-of-range answers and stores a score.
  4. Severity and evidence: Medium; priority P2. HTTP regression covers absent, empty, oversized, negative, string, and out-of-range answers.
  5. Fix and verification status: Require exactly one integer option index in range for each question. Status: Fixed & Verified.

BUG-007 Assignments can reference nonexistent lessons

  1. Bug ID and title: BUG-007 — Assignments can reference nonexistent lessons
  2. Location and steps: backend/src/services/assignment.service.js. While enrolled, submit an assignment with a newly generated lesson identifier that is not in the course.
  3. Expected versus actual: The request should fail. The original stores a submission with status 201.
  4. Severity and evidence: High; priority P2. HTTP regression rejects nonexistent lessons, blank answers, and javascript links; a valid answer succeeds.
  5. Fix and verification status: Verify the lesson and assignment prompt belong to the enrolled course; reject blank answers and non-HTTP links. Status: Fixed & Verified.

BUG-008 Assignment grades exceed their valid range

  1. Bug ID and title: BUG-008 — Assignment grades exceed their valid range
  2. Location and steps: backend/src/services/admin.service.js. As an admin, review an assignment with grade 101 or a negative grade.
  3. Expected versus actual: Grades must be numeric values from 0 through 100. The original accepts 101.
  4. Severity and evidence: Medium; priority P2. HTTP regression rejects -1, 101, a numeric string, and an invalid review status; grade 85 succeeds.
  5. Fix and verification status: Validate the grade range and run schema validation during updates. Status: Fixed & Verified.

BUG-009 Admin assignment course filter is ignored

  1. Bug ID and title: BUG-009 — Admin assignment course filter is ignored
  2. Location and steps: backend/src/controllers/admin.controller.js and backend/src/services/admin.service.js. GET /api/admin/assignments?courseId=<an unrelated valid course identifier>.
  3. Expected versus actual: The response should exclude assignments from other courses. The original returns unrelated assignments because the controller drops the query and the service uses the wrong field.
  4. Severity and evidence: Medium; priority P2. HTTP regression checks the matching course and a nonmatching course.
  5. Fix and verification status: Forward req.query and filter on the course field. Status: Fixed & Verified.

BUG-010 Students can change another student progress

  1. Bug ID and title: BUG-010 — Students can change another student progress
  2. Location and steps: backend/src/controllers/enrollment.controller.js and backend/src/services/enrollment.service.js. Student B sends PATCH /api/enrollments/<student A enrollment>/complete-lesson with a valid lesson ID.
  3. Expected versus actual: The request should fail without changing student A progress. The original returns 200 and updates the other enrollment.
  4. Severity and evidence: High; priority P1. HTTP regression verifies cross-student access is rejected.
  5. Fix and verification status: Pass the authenticated student ID and query the enrollment by both ID and owner. Status: Fixed & Verified.

BUG-011 Arbitrary lesson identifiers inflate progress

  1. Bug ID and title: BUG-011 — Arbitrary lesson identifiers inflate progress
  2. Location and steps: backend/src/services/enrollment.service.js. Complete the real lesson, then submit another completion using an identifier outside the course.
  3. Expected versus actual: Only lessons in the course should count and progress should stay at most 100 percent. The original accepts the identifier and reaches 200 percent.
  4. Severity and evidence: Medium; priority P2. HTTP regression rejects an unknown lesson, checks idempotence, and reads persisted progress from MongoDB.
  5. Fix and verification status: Validate course lesson membership, deduplicate stored IDs, and remove stale IDs before counting. Status: Fixed & Verified.

BUG-012 Course updates bypass required field validation

  1. Bug ID and title: BUG-012 — Course updates bypass required field validation
  2. Location and steps: backend/src/services/admin.service.js. As an admin, PATCH a course with an empty title.
  3. Expected versus actual: Required fields should remain valid. The original returns 200 with an empty title.
  4. Severity and evidence: Medium; priority P2. HTTP regression rejects an empty title and verifies the original title remains stored.
  5. Fix and verification status: Enable runValidators for course updates and disallow negative prices in the schema. Status: Fixed & Verified.
